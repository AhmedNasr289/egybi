# Risks & Mitigations

- **Solo, part-time founder bandwidth (still real, even with only one venture now):** Ahmed still has a full-time job; the risk shifted from "splitting time across two ventures" to "the usual side-project time-scarcity risk" once EGYBi WFM was dropped (see [[Relationship to EGYBi]]) — mitigated the same way as before, by the deliberately thin 2-of-9-track MVP scope below.
- **Brand-name collision:** "Seshat" was rejected specifically because two Egypt-based tech firms and an established open-source history databank already use it — a real risk in exactly this market. "Per Ankh" (the working name this platform was designed under, before renaming to **EgyBI**) checked clean against tech/SaaS competitors. **"EgyBI" itself was checked (2026-07-18) — no existing tech company, SaaS product, or BI platform uses this exact name.** The one near-collision worth remembering: **egabi.com**, a real, established Egyptian enterprise-software integrator (banking/government IT across Egypt/Saudi/UAE, founded 1999) — different spelling and no distinct "BI" unit in its name, but phonetically close and in the same country/industry space, so worth a mental double-check for confusion risk. A full trademark-registry search (Egypt + WIPO) is still recommended before public launch (see [[Sources]]).
- **Book-copyright exposure:** distinct from EGYBi's employer-data risk — mitigated by the explicit rule in [[IP & Content Rules]] that content is inspired by techniques, never copied from source books.
- **Execution-sandbox security:** running arbitrary user code is a real attack surface. Mitigated by the tiered architecture in [[Product Format & Architecture]] — client-side DuckDB-Wasm for SQL/modeling (zero server execution risk) at MVP, deferring any real server-side code execution to a managed, purpose-built execution API in Phase 2 rather than building custom sandboxing.
- **Competing against DataCamp's content breadth:** mitigated by the format difference identified in [[Competitive Landscape]] — DataCamp is guided-tutorial, EgyBI is competitive/gamified auto-graded practice; different use occasion, not a head-on clone.
- **Thin MVP scope (only 2 of 9 tracks):** a deliberate tradeoff to keep Phase 1 buildable solo — accepted risk, with the growth path in [[Build Plan]] explicit about sequencing the rest.
