# IP & Content Rules

Two separate boundaries apply to this project — both non-negotiable.

## 1. Employer-data boundary (same as EGYBi)
Every practice exercise, dataset, and scenario must be original, synthetic, or drawn from genuinely open/public data — never anything derived from Ahmed's employer's (Teleperformance) real client data, schemas, or internal tools. Same reasoning as EGYBi's clean-room rebuild (see `C:\dev\egybi\vault\Clean-Room IP Constraint.md`): this code and content is built on personal time, personal hardware, with zero employer-derived material, ever.

## 2. Book-copyright boundary (specific to EgyBI)
[[Curriculum & Skill Tracks]] is explicitly grounded in real, named books (Kimball, Inmon, Kleppmann, Reis & Housley, etc.) — this is fine and valuable as a **recommended-reading pointer**, and it's fine to build exercises around the **industry-standard techniques** those books teach (e.g. "SCD Type 2," "star schema," "clustering key," "idempotent ingestion" are generic technical vocabulary, not anyone's property). It is **not** fine to copy actual exercise text, sample datasets, diagrams, or substantial passages from those books into the platform — that would be real copyright infringement, distinct from and in addition to the employer-data risk. Every exercise must be an original scenario Ahmed (or a reviewed community contributor) writes from scratch, inspired by a concept, never lifted from a source.

## Standing rule for every future session on this project
No TP client names, schemas, real data, or literal TP code — ever, anywhere in this platform. No copied book content — ever, anywhere in this platform. Reading-list citations point learners *to* the books; they are never a source to paste *from*.
