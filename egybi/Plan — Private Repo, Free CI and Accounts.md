### The guard, so it never runs out silently

1. **In the repo (Claude builds it).** A daily `usage-guard.yml` sums this month's billable minutes the same way the table above was measured. `GITHUB_TOKEN` with `actions: read` can list runs and jobs, so no new secret is needed.
   - **70% (1,400 minutes):** it opens an issue titled "Actions minutes at N% of the month".
   - **90%:** a second issue.
   - Notifications come from GitHub, so no email is sent in your name.
2. **🖥️ Web console (you).** github.com/settings/billing → **Budgets and alerts** → keep the Actions budget at **$0** with **Stop usage** on, and tick the alert emails at 75%, 90% and 100%. GitHub sends those alerts to you; nothing is sent in your name.
3. **Fallback.** If Actions is ever blocked, the scheduled hand refresh already fills the day in (it stands down by itself while Actions works).

## 2. Free sign-up and sign-in

**Most of the server side exists and is sound.** The work is to:
- put it on the page;
- add account deletion;
- give a signed-in reader something worth signing in for.

No paid service is needed: PHP and MySQL on Hostinger, plus Hostinger mail.

| Requirement | Today | To do |
|---|---|---|
| Password hashing | `hash_password()`: Argon2id, bcrypt fallback, 8–128 characters | Nothing |
| Email verification | Token valid 24 h, link `/?verify=…` | Make the landing page show a clear "verified" or "link expired" message (the token flow exists; the page message must be checked) |
| Password reset | Generic reply (no enumeration); a reset kills all sessions | Nothing on the server; UI only |
| Mail | `mailer.php` sends through `smtp.hostinger.com` (465 SSL or 587 STARTTLS), **only if** SMTP is filled in `_private/config.php`. Otherwise it logs the first 8 characters of the token | **Check whether SMTP is configured** (open question 2). `auth.php?action=mail-test` sends one real email, so it runs **only after your yes**, to your own address. Hostinger's sending limit per mailbox is **unverified**: read it in hPanel → Emails |
| Session cookie | HttpOnly + Secure + SameSite (per `auth.php`) | Prove it live: one test login, then read the `Set-Cookie` header |
| CSRF | Token returned by `login` and `me`, required on writes | Nothing |
| Rate limits | e.g. signup 8 an hour per IP, plus per-account buckets | Nothing |
| Account deletion | **Missing** | New `delete-account` action: POST, CSRF, password re-entered. In one transaction, delete the user's sessions, tokens, trips, progress and stats, then the user row. Reply, then clear the cookie |
| Data export | Missing | New `export` action: JSON of the user's own rows (privacy page promise) |
| Privacy page | Written for anonymous use | Add: what an account stores, for how long, and how to delete it |

**What a signed-in reader gets:**
1. **Saved trips** synced across devices. `trip.js` keeps working anonymously in localStorage, and on sign-in offers to copy those trips to the account.
2. **Saved places**: a star on Places and on the `visit/` pages.
3. **Newsletter preference** in the same account.

The SQL-practice progress tables stay (kept, not used).

**New tables** (MySQL, added to `schema_auth_mysql.sql` the same way as the existing ones, and also to the SQLite schema for local tests):
```sql
CREATE TABLE IF NOT EXISTS user_trips (
  id         VARCHAR(32)  NOT NULL PRIMARY KEY,
  user_id    VARCHAR(32)  NOT NULL,
  title      VARCHAR(120) NOT NULL,
  data_json  MEDIUMTEXT   NOT NULL,      -- the trip.js object, size-capped at 64 KB in PHP
  created_at VARCHAR(32)  NOT NULL,
  updated_at VARCHAR(32)  NOT NULL,
  INDEX (user_id)
);
CREATE TABLE IF NOT EXISTS user_saved_places (
  user_id    VARCHAR(32)  NOT NULL,
  place_key  VARCHAR(80)  NOT NULL,      -- the key geo-places.json already uses
  created_at VARCHAR(32)  NOT NULL,
  PRIMARY KEY (user_id, place_key)
);
```

**Changes in `auth/`:**
- `auth.php` gains `delete-account`, `export`, `trips-list`, `trips-save`, `trips-delete`, `places-toggle` and `places-list`. Every write is POST + CSRF + same-origin; every query is prepared.
- `lib.php` gains `with_tx(callable)` for the delete.

**Entry points:**
- **Every page:** an account control in the header ("Sign in", or the reader's display name). It loads `auth.js` lazily on first click, so anonymous readers download nothing extra.
- **`plan.html`:** "Save this trip to my account".
- **`places.html` and the 18 `visit/` pages:** a "Save place" star.
- **A new `account.html`:** saved trips, saved places, newsletter, export, delete. It is `noindex`.

**Accessible and mobile-first:** a full-screen modal on phones and a centred dialog from 768 px. Focus is trapped and returned. `aria-live` carries error messages. Labels sit outside the fields. Controls are at least 44 px. It works with keyboard only. CI's `a11y2.js`, `tap-targets.js` and `overflow.js` already check these and will cover the new markup.
