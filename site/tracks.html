The curriculum

Nine tracks, beginner to advanced.

Each track is grounded in a real, respected book — and every exercise is built on real Egyptian data, from pharaoh chronology to the Met Museum's open collection. You learn the modern data stack and absorb real history at the same time.

Career paths

Which specialization are you building toward?

The 9 tracks below combine into three real data-career specializations. Follow one end-to-end, or mix them — every path starts with SQL.

Data Engineering

Build & run the pipelines.

Ingest, orchestrate, and scale data in production.

Path: SQL → Python → Airflow → Spark → Cloud Warehouses → Data Quality

Analytics Engineering

Model & transform the data.

Turn raw tables into trusted, tested, well-modeled datasets.

Path: SQL → Dimensional Modeling → dbt → Data Quality

BI Development

Turn data into decisions.

Design the models, measures, and dashboards a business runs on.

Path: SQL → Dimensional Modeling → BI Tooling → Cloud Warehouses

All nine tracks in detail
Beginner → Advanced

1 · SQL Fundamentals & Advanced

Grounded in: SQL Antipatterns (Karwin), SQL Performance Explained (Winand).

  • Longest Reigns — rank pharaohs by reign length; window-function variant partitions by dynasty.
  • The Family Line — self-join the pharaohs table to reconstruct father→son succession chains.
  • Missing Monuments — anti-join UNESCO sites against monuments to find the gaps.
  • Co-Regency Overlap — detect illogical reign-date overlaps, allowing for real co-regencies.
Intermediate → Advanced

2 · Dimensional Modeling & Data Warehousing

Grounded in: The Data Warehouse Toolkit (Kimball), Building the Data Warehouse (Inmon), Star Schema (Adamson).

  • Monument Star Schema — build fact_monument_construction against pharaoh, dynasty & location dimensions.
  • SCD Type 2 — model the Great Sphinx's disputed attribution as slowly-changing history.
  • Conformed Dimensions — share dim_dynasty across monument and reign fact tables.
  • Star vs Snowflake — normalize dim_location into site → region → UNESCO hierarchy.
Intermediate

3 · Orchestration (Airflow)

Grounded in: Data Pipelines with Apache Airflow (Harenslak et al.).

  • Live Ingestion DAG — pull the Met Museum's real nightly Egyptian-art CSV, land it, trigger transforms.
  • Backfill — recompute dynasty-level aggregates after a schema change.
  • Sensor Trigger — wait for the Met's nightly file update before running.
  • SLA Alerting — fire an alert if the ingestion DAG misses its window.
Intermediate

4 · dbt & Analytics Engineering

Grounded in: Analytics Engineering with SQL and dbt (Machado & Russa).

  • Model Layers — build staging → intermediate → mart on the real Met dataset.
  • Test Suite — pass not_null / unique / relationships tests.
  • Incremental Model — process only Met objects updated since the last run.
  • Disputed-Date Macro — consistently handle "circa"/disputed dates across models.
Advanced

5 · Spark / PySpark

Grounded in: Learning Spark (Damji et al.), Designing Data-Intensive Applications (Kleppmann).

  • Partition Skew — partition the ~30k-row Met dataset by era; detect and fix skew.
  • Broadcast Join — broadcast the tiny dim_dynasty against a large fact table.
  • Rolling Window — moving-average the real Nile flood-level series.
  • Idempotent Ingestion — exactly-once load of the Deir el-Medina records.
Advanced

6 · Cloud Data Warehouses

Grounded in: Snowflake: The Definitive Guide (Avila). Snowflake + BigQuery to start.

  • Clustering Key — choose and justify a clustering key for the Met CSV.
  • Semi-structured JSON — query the Met API's nested artist/constituent fields.
  • Time Travel — recover from a bad UPDATE to a monument-attribution field.
  • Cost Tuning — full-scan vs pruned query on the Nilometer time series.
Beginner → Intermediate

7 · BI Tooling

Grounded in: Storytelling with Data (Knaflic). Power BI & Tableau mechanics.

  • Construction Gantt — a timeline of monument-construction eras across dynasties.
  • Reign Measures — a DAX/calculated measure for average reign length by era.
  • Flood Anomalies — visualize the Nile flood record, highlighting outlier years.
  • Fix the Chart — redesign a misleading dual-axis "monuments vs reign length" chart.
Intermediate

8 · Data Quality & Testing

Grounded in: Data Quality Fundamentals (Moses, Gavish, Vorwerck).

  • Overlap Validation — no two same-dynasty pharaohs illogically overlap (co-regency allowlist).
  • Freshness Check — alert if the Met's nightly CSV hasn't updated in 48h.
  • Anomaly Detection — flag statistical outliers in the Nile flood series.
  • Lineage — when a disputed date shifts, trace which marts need reprocessing.
Beginner → Advanced

9 · Python for Data Engineers

Grounded in: Data Engineering with Python (Crickard), Fundamentals of Data Engineering (Reis & Housley).

  • Resilient Ingestion — a retry/backoff script against the real Met Museum API.
  • Clean the Papyrus — clean a Wilbour-Papyrus-style ~2,800-row land/tax dataset.
  • Pharaoh CLI — a small tool that looks up dynasty/era/reign by name.
  • End-to-End Pipeline — ingest → land → dbt transform → Airflow orchestrate → BI-ready mart.
